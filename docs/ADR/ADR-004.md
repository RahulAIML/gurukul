# ADR-004: Rule-based (deterministic) recommendation engine for Gym MVP

**Status**: Accepted
**Date**: This design phase

## Context
SRS §11 requires "personalized program recommendations based on answers" but doesn't specify the mechanism. Two real options exist: a deterministic lookup table, or an LLM call at onboarding completion. See `DESIGN_PHASE_REVIEW.md` D1.

## Decision
Gym's `RecommendationEngine` (per `CATEGORY_ARCHITECTURE.md` §3) is a deterministic lookup: `{goal, fitnessLevel, equipment, daysPerWeek} → programId`.

## Consequences
- Fast, free, predictable, and fully testable — no dependency on AI Gateway availability/cost for the highest-traffic funnel step.
- Requires maintaining a mapping table as programs are added — an acceptable, low-complexity cost at MVP program-catalogue size.
- LLM-based matching remains available as a Phase 2+ enhancement once enough programs exist that a lookup table becomes unwieldy or fuzzier matching adds real value — not precluded by this decision, just not needed now.
- Directly mitigates SRS §14's "AI Coach Token Costs" risk by keeping the highest-frequency AI-adjacent interaction (every onboarding completion) off the AI Gateway entirely.
