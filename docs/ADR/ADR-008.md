# ADR-008: OAuth scaffolded but not activated in Gym MVP

**Status**: Accepted (confirms existing SRS intent, not a new decision)
**Date**: This design phase

## Context
SRS §9 states "OAuth2 infrastructure ready: Google, GitHub auth scaffolding complete," but SRS §11's MVP auth scope lists only email/password (registration, verification, login, password reset). See `DESIGN_PHASE_REVIEW.md` D4.

## Decision
OAuth routes/strategy stubs may exist in the codebase (per SRS §9) but no real Google/GitHub app registration, credentials, or UI entry point (a "Sign in with Google" button) ships in the Gym MVP or its immediate follow-on phases.

## Consequences
- Prevents a developer from prematurely building full OAuth UI/flows against SRS §9's "ready" language without checking §11's actual MVP scope.
- OAuth activation becomes an explicit, scoped task in a later roadmap phase when there's a product reason to prioritize it (e.g., registration friction data suggesting it's worth the investment) — not a default assumption baked into MVP work.
