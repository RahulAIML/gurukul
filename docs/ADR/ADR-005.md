# ADR-005: Single-select goal in onboarding (not multi-select)

**Status**: Accepted
**Date**: This design phase

## Context
SRS §5's `Goals` collection has a singular `goal_type` field (not an array), and SRS §11 describes onboarding as capturing "fitness goals" as one step, but doesn't explicitly rule multi-select out. See `DESIGN_PHASE_REVIEW.md` D2.

## Decision
Goal Selection (`UX_ARCHITECTURE.md` §5) is single-select. This matches the existing `goal_type` singular field exactly — no data model change required.

## Consequences
- Cleaner recommendation logic (`ADR-004`'s lookup table has one goal dimension, not a combinatorial set).
- A user wanting to pursue multiple goals simultaneously isn't directly supported in v1 — they can update their goal later (Goals screen, `UX_ARCHITECTURE.md` §8) but not hold two active goals at once. This is a real product limitation, flagged as a possible Phase 2+ feature (multi-goal support), not silently precluded — it would require both a data model change (`goal_type` → array) and a `RecommendationEngine` redesign.
