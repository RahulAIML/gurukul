# ADR-012: Athletic red/carbon visual direction (supersedes ADR-011)

**Status**: Accepted — supersedes the Gurukul-era brass direction in `ADR-011` / `VISUAL_LANGUAGE.md`
**Date**: Implementation slice 1

## Context
`ADR-011` adopted a warm brass-and-parchment, Gurukul-era direction after the user found the first (cool navy) direction too cold. Having then seen that direction built out, the user supplied a new reference — a red-on-near-black athletic layout — and asked for the UI to move to it.

This is the third visual direction. It is a client decision made with each prior option actually built and viewed, so it is recorded rather than argued.

## Decision

**Palette** — near-black carbon grounds with a vivid athletic red:

| Token | Hex | Role |
|---|---|---|
| `carbon` | `#0A0A0C` | Base ground |
| `carbon-2/3/4` | `#121216` / `#191920` / `#22222B` | Raised surfaces, cards, hover |
| `ember` | `#E4262F` | Primary accent, CTAs |
| `ember-lit` / `ember-deep` | `#FF4A52` / `#A8161D` | Hover / shadow end of body gradients |
| `chalk` | `#FFFFFF` | Primary text |
| `chalk-dim` / `chalk-mute` | `#9A9AA8` / `#6B6B78` | Secondary / tertiary text |

**Typography** — **Archivo** 800 uppercase with tight tracking for display, **Inter** for body. Replaces Marcellus/Cormorant/Mukta.

**Ornament** — the arch, jali lattice, rosette and Devanagari accents are removed. Atmosphere now comes from a single red light source (`ember-glow`) and a very faint 56px grid.

## Contrast

White on `#E4262F` is **4.55:1** — passes WCAG AA for normal text, which is why button labels are white rather than near-black (`#0A0A0C` on ember is 4.32:1 and would fail). Worth preserving if the red is ever retuned: darkening `ember` improves button contrast, lightening it breaks AA.

## What carries over unchanged

Structure is untouched: information architecture, journeys, the question schema and engine, routing, persistence, motion principles, the accessibility baseline, and the whole backend/API/database architecture. Only palette, type and ornament changed — the same separation that made `ADR-011` cheap to apply.

## Consequences

- `VISUAL_LANGUAGE.md` is superseded for palette, typography and ornament. Its §2 boundary (no deity or religious imagery) is moot under this direction, which carries no cultural iconography at all.
- The avatar layer was rebuilt around the new accent: figures are drawn with an ember body gradient and a steel gradient for equipment.
- Devanagari is gone from the UI. If the brand later wants that thread back, it should return deliberately rather than as a leftover.

## Related: the avatar iteration

Three rounds were needed before the figures read as adult:

1. **Hairline stroke figures** — read as crude stick figures at 76–96px. Cause: stroke weight far too light for the render size.
2. **Heavy stroke figures** — better, but read as toys. Cause: the head was ~21% of figure height and the legs ~32%.
3. **Current** — filled physique silhouettes on an **8-head adult canon** (head ~12.5% of height, hips at the exact halfway point) with **articulated tapered limbs** and gradient shading.

Two lessons worth keeping:

- **Proportion, not detail, decides whether a stylised figure reads as an adult.** Head size and leg length did all the work; added detail did none of it.
- **Limbs must be drawn as per-segment shapes with joints, not one polygon through every point.** A single polygon self-intersects the moment a limb folds back (a flexed bicep), which renders as a spike — this shipped visibly in round 2 and was only caught by inspecting the avatars at 190px rather than at their real 96px size.

The set remains **original inline SVG**, not the photographic/3D renders the reference funnel uses; those cannot be produced here. `avatars/registry.tsx` is the single swap point, so replacing them with commissioned or generated artwork touches one file.
