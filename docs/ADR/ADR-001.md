# ADR-001: Reconcile SRS's 14-week roadmap with the 8-month design+build timeline

**Status**: Accepted
**Date**: This design phase

## Context
SRS §12 defines a 14-week roadmap for the Gym MVP (landing → auth/onboarding → programs → progress → AI → payments → polish → launch). The Design + System Architecture Phase brief states ~8 months total, with a dedicated design/architecture phase preceding implementation and a 30-screen conceptual inventory. These are not the same schedule for the same scope — see `DESIGN_PHASE_REVIEW.md` Conflict 1.

## Decision
The SRS §12 roadmap's **phase content and order** (landing → auth/onboarding → programs/workouts → progress → AI coach → payments → polish → QA) is retained as the backbone of the roadmap. It is **stretched to 8 months**, with a new **Phase 0** (this design phase, ~4–6 weeks) inserted before implementation begins, and each subsequent phase given realistic multi-week duration instead of the original 1–2 week compressed slices. SRS §12 is marked superseded (not deleted) and kept for historical reference.

## Consequences
- `ROADMAP.md` reflects this 8-month structure, not SRS §12's 14-week one.
- Same MVP scope ships, built more deliberately, with room for the design system and category architecture to be validated before mass implementation.
- Risk: if scope quietly grows to fill the extra time (SRS §14's own "Scope Creep" risk), the 8 months could be consumed without shipping more than the original 14-week plan would have. Mitigation: `ROADMAP.md`'s phase gates (brief §36) are the control for this.

User, via direct confirmation during this design phase (see `DESIGN_PHASE_REVIEW.md` §8).
